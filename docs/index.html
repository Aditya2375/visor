visor

A type-2 hypervisor for Linux on the KVM kernel API, in C. Every line of guest output below is real.

Why a replay instead of an in-browser run?

visor runs guest code on the CPU itself through /dev/kvm - hardware virtualization. A browser tab has no KVM (and WebAssembly cannot provide one), so there is nothing to run it on here. What this page replays instead is the exact console transcript the CI guest suite verified byte-for-byte against real KVM runs: each visor run build/guests/<name>.img below prints the output recorded in guests/<name>.expected, which the harness compares live against the guest's actual output on every push, plus the host-side guest exit: 0 report. The five guests pass on real hardware in CI - see the run.

The five guests

hello writes to a virtual serial port; ints triggers int3, runs its handler and returns with iret; mmio probes an unmapped device region; pmode enters 32-bit protected mode inside the guest; spin loops forever until the watchdog timer tears the VM down. Sources are in guests/ next to each expected transcript.

Run it yourself

On any Linux host with KVM: make, then ./build/visor run build/guests/hello.img. The full suite is ./tests/run-guest-tests.sh (it skips cleanly where /dev/kvm is absent).
